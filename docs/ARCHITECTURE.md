# Устройство проекта

## Основной путь запроса

Браузер (React) → HTTP-сервер Node.js → общее ядро handleStudio → локальная SQLite / API xAI → сохранение результата → браузер или ZIP.

Для обычного запуска нет обращений к Sites, Cloudflare или OpenAI. Внешний сервис нужен только для генеративного редактирования: xAI. Профиль Sites оставлен отдельно; в нём тот же обработчик использует R2.

## Данные

DATA_DIR/afisha.sqlite содержит таблицу objects. Поля: key (уникальный логический путь), etag (UUID ревизии), size, metadata (JSON), http (MIME-тип в JSON), data (BLOB изображения или JSON задания).

Объекты размещаются под sessions/{session}/assets/{id}, jobs/{id}, results/{id}, config. Оригинал и результат — отдельные объекты. Имя исходного файла хранится в метаданных, а не используется как путь ОС. При чтении списка не выбираются BLOB, поэтому список не загружает все фотографии в память.

SQLite работает в WAL-режиме с busy_timeout=5000 и user_version=1. Дальнейшие версии должны вводить явные последовательные миграции. Не размещайте базу на NFS. Приложение рассчитано на один сервер с локальным диском.

Серия привязана к случайной HttpOnly cookie браузера. Очистка cookies создаёт новую серию, но сама по себе не удаляет старые данные. Общий пароль не является системой пользовательских аккаунтов и не восстанавливает cookie.

## Жизненный цикл задания

pending → running → done либо error. Из error доступен ручной возврат в pending. Из зависшего running возврат разрешён через 10 минут. ID задания совпадает с ID фотографии. Пара фотография/макет и настройки фиксируются при создании очереди. extend добавляет только ещё не назначенные фотографии.

Захват задания использует сравнение etag. SQLite проверяет ревизию и записывает новую внутри BEGIN IMMEDIATE; другой запрос со старой ревизией получает конфликт. В R2 применяется условная запись. Повторный edit для done возвращает сохранённый результат без нового запроса к xAI.

Это не гарантия exactly-once для внешнего API: при сбое после принятия запроса xAI факт оплаты может остаться неизвестным. Автоматических платных повторов нет.

## Параллельность и память

Браузер отправляет от 1 до 4 запросов, по умолчанию 2. Следующее задание стартует после освобождения слота. Дополнительная оценка памяти учитывает размеры изображений, base64/JSON-копии и ответ. Она снижает параллельность для крупных файлов, но не гарантирует точное потребление RAM.

Node.js дополнительно ограничивает одновременно активные edit на весь процесс через MAX_ACTIVE_EDITS. При превышении выдаётся 429 до вызова провайдера. Пауза или первая ошибка останавливают новые отправки, уже отправленные завершаются и сохраняются независимо друг от друга.

Очередью управляет открытая вкладка. Полностью серверный диспетчер с восстановлением после рестарта, защищённым хранением ключей и политикой повторных расходов пока не реализован. Автономность текущей версии относится к развёртыванию.

## xAI

На задание отправляется POST https://api.x.ai/v1/images/edits: model, prompt, два images (сначала фото, затем макет), n=1, response_format=url. Исходники передаются как data URI. Таймаут генерации 240 секунд, загрузки результата 45 секунд. Также обрабатываются ответы b64_json.

URL результата разрешён только по HTTPS на x.ai или поддоменах; редиректы запрещены. Максимальный результат 18 МБ, его сигнатура проверяется перед сохранением. Размеры и типографику генеративная модель может изменить.

## Безопасность

- APP_PASSWORD от 16 символов обязателен при внешнем прослушивании. Basic Auth нужно использовать через HTTPS.
- POST проверяет Origin против настроенного APP_ORIGIN.
- Cookie: HttpOnly, SameSite=Strict, Secure при HTTPS origin.
- API-ключ xAI остаётся в памяти вкладки и текущего запроса. Он не пишется в SQLite или localStorage; нельзя помещать его в VITE_*.
- SQLite не шифруется приложением: права ОС и защита резервных копий обязательны для закрытых данных.
- HTTP-сервер ограничивает размер тела, включая chunked upload; SVG не принимается как фотография.
- Логи не содержат ключей и тел запросов.

Для публичного многопользовательского сервиса потребуются индивидуальные аккаунты, квоты диска, ограничения попыток входа на reverse proxy, аудит и распределённая очередь. Сейчас это личная установка или инструмент небольшой доверенной команды.
