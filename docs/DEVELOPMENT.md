# Разработка и тестирование

## Установка и команды

Node.js 24.12+. Используйте npm ci с закоммиченным lockfile.

| Команда | Назначение |
|---|---|
| npm run dev | Node API + Vite HMR на одном порту |
| npm run build | Самостоятельный интерфейс в dist/web |
| npm start | Node-сервер со статической сборкой |
| npm run typecheck | TypeScript без генерации файлов |
| npm run lint | Проверка app/lib/frontend |
| npm test | Все *.test.mjs |
| npm run dev:sites | Дополнительный локальный профиль Sites/Cloudflare |
| npm run build:sites | Дополнительная Worker-сборка |

Серверный код использует встроенный node:sqlite и запускает общее TypeScript-ядро через поддерживаемое Node.js удаление аннотаций типов. Не добавляйте в импортируемое сервером ядро TypeScript-конструкции, требующие трансформации (например, enum или parameter properties). В серверных импортах используются явные .ts-расширения; alias @ доступен только сборщику интерфейса.

## Тесты

- core.test.mjs: равномерность назначения, случайный/последовательный режим, сигнатуры, ZIP.
- concurrent.test.mjs: 100 задач, максимум слотов, остановка после ошибки, дренирование при паузе, ограничение памяти.
- standalone.test.mjs: SQLite и etag между соединениями, pagination, Basic Auth, загрузка/назначение/обработка/ZIP, рестарт и изоляция cookie. Вызов xAI заменяется тестовой функцией, платных запросов нет.
- api.mjs: дополнительная проверка уже запущенного локального сервера первоначального профиля. Не включена в npm test; адрес зафиксирован в скрипте, при защищённом Node-сервере используйте standalone.test.mjs.

Тесты не доказывают качество генеративной замены. После установки выполните пробу на реальном фото с собственным ключом. На подготовительной машине Docker Engine был недоступен. GitHub Actions настроен на npm ci, typecheck, тесты, сборку и docker build; результат конкретного workflow проверяйте в Actions.

## Расширение

Новый провайдер: вынесите вызов модели из lib/studio.ts в адаптер, задайте отдельную серверную конфигурацию и валидацию ответов, добавьте mock-тесты. Нельзя просто подставлять произвольный URL от клиента: это создаёт риск SSRF и утечки ключа.

Новое хранилище: реализуйте lib/storage-types.ts. Критичны атомарная условная запись etag, согласованность метаданных и bytes, prefix-list с пагинацией. Без compare-and-swap возможны двойные платные запросы.

Фоновая очередь: нужны серверный диспетчер, политика хранения ключей и их удаления, лизинг задач, восстановление после рестарта и обработка неопределённого результата xAI. Не считайте обычный fetch в браузере фоновой задачей.

## Совместимость Sites

Старые пакеты vinext, Cloudflare и Sites оставлены для дополнительного профиля и сохранения существующей установки. Они не импортируются самостоятельным сервером и отсутствуют в финальном Docker-образе. .openai/hosting.json относится к прежней установке. Не публикуйте в чужой проект и не используйте этот ID для создания новой установки Sites.

Для обычного сервера не требуются ни этот manifest, ни разрешения Sites. Сборка выбирает профиль по SITE_TARGET; scripts/sites.mjs задаёт его только для отдельных команд. Автономный сервер не переносит данные из R2 автоматически.

Worker-сборка может очистить каталог dist. После build:sites перед обычным npm start снова выполните npm run build.

## Обслуживание зависимостей

Версии закреплены в package-lock.json. Проверяйте npm audit, release notes и регрессионные тесты перед обновлением. Унаследованный комплект UI/Sites содержит зависимости, не используемые сервером production; отсутствие node_modules в финальном контейнере сокращает его runtime-зависимости, но не отменяет аудит цепочки сборки. Не применяйте npm audit fix --force без разбора совместимости.

Не коммитьте .env, базы SQLite, фотографии, cookies, ключи, архивы сборки и токены Git. Проверяйте git diff --cached перед push.
