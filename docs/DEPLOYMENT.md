# Развёртывание и эксплуатация

## Требования

Node.js 24.12+ и npm либо Docker Engine с Compose v2 (Linux-контейнеры). Рекомендуемая начальная VPS-конфигурация: 2 CPU, 2 ГБ RAM, локальный диск с запасом. Это оценка для начала, не результат нагрузочного теста. GPU не нужен: редактирование выполняется у xAI. Нужен исходящий HTTPS к api.x.ai и поддоменам x.ai.

## Конфигурация .env

Скопируйте .env.example в .env. Файл исключён из Git и Docker build context. Значения читаются при старте.

| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| APP_ORIGIN | http://localhost:3000 | Внешний origin без пути, включая протокол и порт |
| HOST | 127.0.0.1 | Адрес прямого Node-сервера |
| PORT | 3000 | Порт |
| DATA_DIR | ./data | Каталог SQLite |
| APP_PASSWORD | пусто | Только localhost может работать без него; внешнему интерфейсу нужны 16+ символов |
| MAX_ACTIVE_EDITS | 4 | Общий лимит edit на процесс, 1–16 |

Compose задаёт HOST=0.0.0.0, PORT=3000 и DATA_DIR=/data внутри контейнера. Наружу порт опубликован только на 127.0.0.1:3000. API-ключ xAI вводится в интерфейсе, серверной переменной XAI_API_KEY пока нет.

Случайный пароль можно получить локально командой:

```bash
node -e "console.log(require('node:crypto').randomBytes(24).toString('hex'))"
```

## Docker Compose

```bash
git clone https://github.com/rdv77/pictures_insert.git
cd pictures_insert
cp .env.example .env
# Задать APP_PASSWORD и APP_ORIGIN в .env.
docker compose up -d --build
docker compose ps
docker compose logs --tail=100 app
```

Образ многостадийный: сборка выпускает dist/web, финальный образ содержит Node, сервер и статику без node_modules, Sites или Cloudflare. Процесс работает от node. Именованный том afisha-data сохраняется при пересоздании контейнера. Не выполняйте docker compose down -v, если данные нужны.

Локально откройте http://localhost:3000. Для проверки VPS до домена можно использовать SSH-туннель:

```bash
ssh -L 3000:127.0.0.1:3000 user@server
```

## HTTPS

1. Направьте A/AAAA домена на VPS.
2. Установите Caddy по https://caddyserver.com/docs/install.
3. Возьмите deploy/Caddyfile, замените afisha.example.com на свой домен.
4. Откройте входящие 80/443. Порт 3000 наружу не требуется.
5. Установите APP_ORIGIN=https://ваш-домен, выполните docker compose up -d.
6. Перезагрузите конфигурацию Caddy.

Caddy на хосте проксирует в 127.0.0.1:3000 и управляет сертификатом. Basic Auth проверяет приложение. Нельзя передавать пароль через HTTP в интернете. Для другого reverse proxy: разрешите тело не меньше 11 МБ, ожидание ответа не меньше 300 секунд, сохраните Authorization.

## Прямой Node.js и systemd

```bash
npm ci
npm run build
npm start
```

В PowerShell копирование конфигурации: Copy-Item .env.example .env. Для постоянной Linux-службы создайте отдельного пользователя и адаптируйте пример:

```ini
[Unit]
Description=Afisha Studio
After=network.target

[Service]
Type=simple
User=afisha
WorkingDirectory=/opt/pictures_insert
EnvironmentFile=/opt/pictures_insert/.env
ExecStart=/usr/bin/node /opt/pictures_insert/server/index.mjs
Restart=on-failure
TimeoutStopSec=360
UMask=0077

[Install]
WantedBy=multi-user.target
```

Укажите абсолютный DATA_DIR=/var/lib/afisha, создайте каталог с владельцем службы. Проверьте путь и версию Node от имени этого пользователя. Для Windows локальный запуск npm start достаточен; постоянная служба требует выбранного администратором менеджера служб.

## Обновление

Приостановите очередь, дождитесь запросов, сохраните резервную копию.

```bash
git pull --ff-only
docker compose up -d --build
```

Для Node: остановить службу → git pull --ff-only → npm ci → npm run build → запустить службу. Не удаляйте DATA_DIR/том. Будущие несовместимые миграции потребуют инструкции релиза.

## Резервная копия

Копируйте весь каталог данных при остановленном приложении. SQLite может использовать WAL/SHM, поэтому копирование одного файла работающей базы не является безопасной процедурой.

```bash
mkdir -p backups
docker compose stop app
docker compose cp app:/data ./backups/data-copy
docker compose start app
```

Для каждой копии выбирайте новое имя каталога. Резервная копия содержит изображения: храните её закрыто. В прямом Node-варианте остановите процесс и скопируйте весь DATA_DIR средствами ОС.

Восстановление: остановить сервер; сохранить текущие данные отдельно; заменить содержимое DATA_DIR/тома выбранной копией; проверить права владельца; запустить. Для доступа к прежней серии нужна прежняя cookie браузера. Проверьте восстановление на тестовой установке.

SQLite может не уменьшить файл после удаления серии, а повторно использовать освобождённые страницы. При необходимости DBA выполняет VACUUM после остановки и резервирования стандартными инструментами SQLite.

## Мониторинг и масштабирование

GET /healthz возвращает ok без пароля — это только доступность процесса, не проверка xAI, свободного места или качества модели. Контролируйте RAM и диск отдельно. Compose содержит healthcheck, restart: unless-stopped и 6 минут для остановки активных запросов.

Одна установка рассчитана на локальный SQLite-каталог. Не используйте NFS, независимые тома под общим балансировщиком или множество реплик без отдельной архитектуры очереди. MAX_ACTIVE_EDITS действует на один процесс.

## Перенос с Sites

SQLite и прежнее R2 — разные хранилища. Данные и браузерные сессии не переносятся автоматически. Скачайте результаты старого сайта, сохраните исходники и при необходимости загрузите их в новую установку. Действующий сайт не требуется менять для запуска автономной копии.

## Статус проверки

Node-сервер, SQLite, рестарт и HTTP API проверены автоматическими тестами. Платный xAI требует отдельной проверки с ключом. Dockerfile/Compose и CI-сборка подготовлены; Docker Engine на рабочей машине был недоступен, поэтому локальный запуск контейнера не подтверждён.
